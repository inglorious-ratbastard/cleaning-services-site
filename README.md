#### About This Project - 

##### Professional Cleaning Services Web Application

##### The **Cleaning Services Site** is a full-stack business web application designed for a professional residential and commercial cleaning company. The project combines a clean, modern user interface with a lightweight server-side architecture to create an approachable online presence for a service-based business.

##### The application was developed with an emphasis on **simplicity, usability, visual presentation, and direct customer communication**. Rather than overwhelming visitors with unnecessary functionality, the site focuses on the information and interactions that matter most to a potential customer: understanding the services offered, navigating the business's information, and having an easy way to get in contact.

##### <ins>Project Goals<ins>:

##### The primary goal of the application is to provide a professional digital presence that makes it easy for customers to learn about cleaning services and initiate contact with the business.

##### The project was designed around several key principles:

* ##### **Clear communication** — Present business and service information in a straightforward and accessible manner.
* ##### **User-friendly navigation** — Keep important pages and contact functionality readily accessible throughout the experience.
* ##### **Professional visual design** — Use Materialize's responsive design system to create a polished interface appropriate for a professional service business.
* ##### **Direct customer interaction** — Provide customers with an accessible contact workflow rather than relying solely on static business information.
* ##### **Lightweight architecture** — Keep the application relatively simple and maintainable by using ExpressJS and server-rendered EJS templates.
* ##### **Responsive presentation** — Structure the interface so that customers can interact with the site across desktop and mobile screen sizes.

##### <ins>Application Features</ins>:

##### The application includes several features intended to support both the customer experience and the business's ability to receive inquiries.

##### <ins>Service-Oriented Presentation</ins>:

##### The website is structured around a cleaning-services business model, allowing visitors to explore the company's offerings and better understand the type of residential and commercial work available.

##### Content and visual elements are organized to create a clear progression through the site, helping visitors move from discovering the business to taking action.

##### <ins>Call-to-Action Navigation</ins>:

##### Strategic call-to-action elements are incorporated throughout the interface to encourage visitors to take the next step, whether that means learning more about the company or initiating contact.

##### The goal is to reduce unnecessary navigation and make important actions immediately recognizable.

##### <ins>Floating Contact Interface</ins>:

##### A persistent floating contact menu provides customers with a convenient way to access communication functionality without having to navigate back to a dedicated contact page.

##### This creates a more accessible interaction model, particularly for visitors who are browsing service information and decide they want to reach out.

##### <ins>Contact Form Processing</ins>:

##### The application includes server-side form processing using **Nodemailer**. Submitted contact information can be delivered directly to a configured email address, allowing customer inquiries to reach the business without requiring the visitor to manually open an external email client.

##### This creates a simple communication pipeline:

##### **Customer → Website Form → Express Server → Nodemailer → Business Email**

##### <ins>Responsive Material Design</ins>:

##### The front end uses **Materialize CSS** to provide a responsive, component-based design system. Materialize supplies the application's grid system, navigation components, buttons, forms, typography, and responsive behavior while allowing the site's presentation to be customized around the cleaning-services brand.

##### <ins>Technical Architecture</ins>:

##### The application follows a lightweight Node.js/Express architecture.

##### **Frontend**

* ##### EJS server-rendered templates
* ##### HTML5
* ##### Materialize CSS
* ##### JavaScript
* ##### Responsive Material Design components

##### **Backend**

* ##### Node.js
* ##### ExpressJS
* ##### Nodemailer
* ##### Body-parser

##### **Deployment**

* ##### Designed for deployment as an Express web application
* ##### Previously configured for hosting through Render
* ##### Environment-specific configuration can be supplied through deployment environment variables

##### The repository is primarily composed of **EJS templates and JavaScript**, with GitHub currently identifying EJS as the dominant language in the project.

##### <ins>Design Philosophy</ins>:

##### The application intentionally follows a **"less is more"** approach.

##### For a local service business, the website does not need to behave like a large enterprise platform. Its primary responsibility is to establish credibility, communicate what the company offers, and provide visitors with a simple path toward contacting the business.

##### The interface therefore emphasizes:

##### > **Information → Trust → Action**

##### Every major design decision supports one of these three objectives.

##### The visual design provides enough structure and personality to distinguish the business while avoiding unnecessary complexity that could distract visitors from the primary purpose of the site.

##### <ins>What This Project Demonstrates</ins>:

##### From a development perspective, this project demonstrates the ability to build a complete web application around the needs of a real-world service business.

##### It showcases experience with:

* ##### Building an ExpressJS application from the ground up
* ##### Creating server-rendered pages with EJS
* ##### Implementing responsive interfaces with Materialize CSS
* ##### Designing user-focused navigation and call-to-action elements
* ##### Processing HTML form submissions on the server
* ##### Integrating Nodemailer for automated email delivery
* ##### Structuring a Node.js application for deployment

##### <ins>Project Context</ins>:

##### This project was created as an **entrepreneurial web application** rather than simply as a static front-end exercise. The intent was to approach the website as a functional product for a service-based company, considering both the technical implementation and the customer's experience.

##### The result is a lightweight platform that combines a professional business presentation with practical communication functionality, demonstrating how relatively simple technologies can be assembled into a complete and deployable web application.

##### **Getting Started:** 
##### Before proceeding with the following steps it is assumed that both [Node.js](https://nodejs.org/en/download/) and [Git](https://git-scm.com/downloads) have been downloaded locally on your system. <br> If not, they can be obtained by clicking on the links provided. Further assistance can be found in the documentation if necessary. 
##### 1. **Clone** this repository `$ git clone https://github.com/cleaning-services-site.git`
##### 2. In the terminal/command prompt run the `npm install` or `yarn install` command to install the projects dependencies
##### 3. Run the `node index.js` command in the terminal to start the server and run the application
___
##### Deployment to Render:
##### About: The following explains how this app was deployed to [Render](https://render.com/) Cloud Hosting, assuming that you have already set up an account. Another preferred option for hosting services would be [Railway](https://railway.app/)
##### * Assure that your project has successfully been committed to Github. Any future changes made and pushed up will be directly reflected on **Render**. 
##### * From the Dashboard click on **New** to connect your Github repo and create your hosted application from the given options (either Static Site or Web Service). 
##### * Name your projet then scroll down and make sure that the `yarn build` and `yarn start` point to the correct files. *See the Scripts section of `package.json` file for clarification.*
##### * If you have any global or secret keys you can create them by expanding the **Advanced** tab and manually entering the proper values in the form boxes provided.
